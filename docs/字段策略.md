# 字段策略

字段提示词明确将“未提及／未描述／未提示”判为 `false` 时，运行时注册表使用 `absence_false` 标明该例外：输出 `value=false, mentioned=true, evidence=null`，不编造病历原文；有原文依据时仍须引用。其他字段沿用通用缺失事实结构。当前例外名单以代码注册表为准。


适用规则版本：`2.2.0`。

本表汇总当前 2.2.0 规则所需的原始事实、程序计算条件与输出变量，供人工审核。原始事实的类型、单位、缺失默认值和实际发送给模型的提取说明集中在 `src/medi/grading/field_registry.py`；JSON 的严格校验仍由 `src/medi/grading/models.py` 执行。本表不被程序直接解析，两者不一致时应同步修正。

LLM 提取的全部字段都必须出现在原始事实表中。仅注册表标明 `absence_false` 的字段可按专属提示词将未记载情况表达为 `mentioned=true, value=false, evidence=null`；其余未提及字段保持 `mentioned=false, value=null, evidence=null`。下表“LLM 提取提示词”已同步到代码注册表，布尔提示词不直接要求输出 `null`；信息不足时仍由通用提取契约生成缺失事实。表中 12 个 `false` 默认值均已在代码注册表启用：规则计算按默认值判断，不再为这些字段展开相反状态；未配置默认值的缺失字段继续保留可能结果。默认值不改写原始事实，也不允许 LLM 输出 `mentioned=false, value=false`；新增默认值时须同步修改注册表并增加验收测试。

提示词语义优先于字段名的日常字面含义：例如 `oxygen_required` 当前判断的是病历是否记载实际吸氧。字段名为现有 JSON 契约，若后续改名，必须同步更新 Schema、规则、界面与测试。

程序计算的条件不由 LLM 输出；其“来源／计算方式”直接填写公式，默认值和提示词记为“—”。表中的这些名称用于解释规则，不表示 LLM 需要额外提取同名字段。

共用提取要求可在注册表的 `SHARED_EXTRACTION_RULES` 中写一次，再通过字段的 `shared_rule_keys` 引用。当前已登记“收缩压与舒张压来自同一次测量”；其他字段组规则待确认后再补。

“其他”列可记录待确认事项；其中“本次急性 PE 评估窗口”的起止点尚未统一定义，暂不据此推断具体时间范围。以后若在“其他”记录数值校验等可执行约束，必须同时在代码 Schema 中实现；此类约束增多后再拆成专列。
