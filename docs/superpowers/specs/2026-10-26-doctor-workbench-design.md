# 医生病历分级工作台设计

状态：用户已明确要求直接实施，跳过草图讨论。

## 目标与边界

保留现有规则引擎和独立规则测试台；新增医生工作台。医生可粘贴病历后提交，或上传 PDF 后立即自动提取文字并运行既有提取→审核→规则工作流，生成所有可能分级；提取的文字可编辑，并可再次提交分析。展示审核状态、可编辑的结构化事实与对应证据；修改事实后无需重新调用 LLM，即可重新计算结果。用流程概览高亮所有可达等级，不把多结果压成单一诊断，也不伪称提供现有规则引擎未记录的逐步证明。

PDF：优先提取文本层；无可用文本的页面通过 OCR 读取；中文和英文 OCR 需要本地 Tesseract 语言数据。识别失败时明确报错，不把空文本送给模型。限制上传大小和页数。仅临时处理，不持久化文件或病历。

FastAPI 替换标准库 HTTP 服务，保留 `/api/config`、`/api/classify` 和 `medi web`，新增医生页面和病例 API。当前仍是受控本地原型：病历会发往外部 DeepSeek，未实现脱敏、认证、审计或临床部署安全控制。

## 用户流程

1. 首页粘贴病历并点击分析，或选择 PDF；PDF 提取完成后自动分析，同时显示可编辑文本供后续修订。
2. 提取、审核、规则计算一次完成，立即展示可能分级。
3. 医生展开字段，修改值/证据并重新计算；规则测试台从导航单独进入。
4. 结果区同时显示每个可达等级及其在规则流程中的位置；缺失值导致多个结果时显式说明。
