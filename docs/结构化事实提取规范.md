# 结构化事实提取规范

| 属性 | 值 |
|---|---|
| 文档状态 | 当前实现 |
| 适用规则版本 | `2.2.0` |
| 输出规模 | 固定 35 个事实对象 |
| 使用组件 | 提取 Agent、审核 Agent |

## 1. 目的与边界

本规范定义如何把一份已确诊目标疾病的病历转换为规则引擎可接受的结构化事实表，以及如何审核和修正该事实表。

提取层只回答“病历记录了什么”，不得回答“患者属于哪个等级”。等级公式、阈值、优先级和缺失值展开属于规则引擎职责，见《规则引擎规范》；LangGraph 重试和路由属于工作流职责。

## 2. 输入与输出

### 2.1 输入

输入是一段 UTF-8 病历文本。上游必须已经确认该病历属于目标疾病；提取 Agent 不负责重新确诊。

修正请求还可以包含：

- `previous_facts`：上一版完整事实表；
- `review_feedback`：审核问题；
- `revision_count`：当前修正次数。

### 2.2 输出

每次提取或修正必须返回一个 JSON 对象，并满足：

- 包含全部 35 个固定字段；
- 不包含未知字段；
- 每个字段都是第 3 节规定的事实对象；
- 修正时仍返回完整事实表，不得只返回发生变化的字段；
- 不包含 Markdown、解释文字、等级或规则推理。

字段集合、类型、单位与实际提示词集中在 `src/medi/grading/field_registry.py`；`src/medi/grading/models.py` 负责严格校验 JSON，`src/medi/grading/parser.py` 核对字段集合并转换错误信息。便于人工审核的字段说明见[字段策略](字段策略.md)，该 Markdown 不由程序直接读取。

## 3. 事实对象契约

### 3.1 已知事实

病历明确支持一个值时：

```json
{
  "value": 92,
  "mentioned": true,
  "evidence": "入院收缩压92 mmHg"
}
```

约束：

- `value` 必须符合字段类型；
- `evidence` 必须是支持该值的病历原文；
- `evidence` 不得为空，不得由模型改写或编造；
- 例外：字段注册表标明 `absence_false` 时，按该字段“未记载即 false”约定得出的 `false` 可用 `evidence=null`，不得编造原文；
- 数值必须先转换为规定的标准单位。

### 3.2 缺失事实

病历没有提供足以确定该字段的信息时：

```json
{
  "value": null,
  "mentioned": false,
  "evidence": null
}
```

缺失信息不得推测、按常见值补齐或默认视为阴性；但注册表标明 `absence_false` 的字段按其专属提示词判断，未记载相应阳性情况时输出 `false/true/null`。其他缺失由规则引擎处理。

### 3.3 明确阴性

病历明确否定一个布尔事实时，必须记录为已知的 `false`：

```json
{
  "value": false,
  "mentioned": true,
  "evidence": "既往无恶性肿瘤病史"
}
```

明确阴性与缺失的语义不同，不得互换。

### 3.4 唯一合法组合

| `mentioned` | `value` | `evidence` | 语义 |
|---|---|---|---|
| `true` | 符合类型的非 `null` 值 | 非空原文 | 已知事实 |
| `true` | `false` | `null` | 仅 `absence_false` 字段按未记载条件判否 |
| `false` | `null` | `null` | 缺失事实 |

其他组合均为无效输入。

## 4. 通用提取原则

### 4.1 忠实提取

- 只提取病历明示或可直接换算的事实；
- 不根据等级阈值反向构造事实；
- 不因为某个值“通常正常”而填入 `false` 或正常数值；
- 不计算 A–E 等级，不在 `evidence` 中加入规则解释。

### 4.2 证据可追溯

- 证据必须能独立支持当前 `value`；
- 不得用只支持相关概念、但不支持目标字段的句子；
- 数值字段的证据应尽量包含数值和原单位；
- 布尔字段的证据应包含明确肯定或否定表述；
- 当前 Schema 每个字段只允许一个证据字符串；需要组合多处信息时，必须保证字符串仍能从原文直接追溯。

### 4.3 单位标准化

数值必须按照字段名和《规则引擎规范》的单位输出。单位转换必须发生在提取层，规则引擎不执行单位识别或换算。

转换后：

- `value` 使用标准单位数值；
- `evidence` 保留病历原文，不得为了匹配转换值而篡改原单位；
- 无法可靠转换时，该字段应保持缺失，不得猜测。

### 4.4 否定、时间点与上下文

- 区分当前状态、既往史和计划性描述；
- 区分患者事实与家族史、鉴别诊断、假设或模板文字；
- “考虑”“待排”“可能”不得自动当作明确肯定；
- 规则字段指定特定事件或用途时，只提取与该上下文相符的值；
- 同一字段存在多个时间点时，必须根据字段定义选择相关时间点，不得任意取极值。

### 4.5 病历冲突

当前 Schema 不支持多值或冲突状态。病历对同一字段存在矛盾时，提取 Agent必须结合时间点和上下文输出一个最终事实，审核 Agent必须重点复核该选择。

若现有字段定义不足以稳定解决某类冲突，应修改提取规范或 Schema，而不是在提示词中形成未记录的隐含规则。

## 5. 字段组与特殊要求

本节只记录提取风险，不重复规则公式。

### 5.1 A、B、C 与 PESI

- `incidental_finding` 与 `asymptomatic` 是两个独立事实，不得互相推导；
- `age_years` 输出岁数，不得由年龄阈值直接输出布尔值；
- `male_sex`、`cancer_history`、`heart_failure_history`、`chronic_lung_disease` 必须基于病历明确记录；心衰与慢性肺病分别提取，不得用笼统心肺疾病代替；
- `body_temperature_c` 使用摄氏度；性别或体温缺失时保持缺失；
- `systolic_bp_mmhg` 同时供低血压、PESI 和 MAP 使用，三处不得分别提取不同收缩压；
- `diastolic_bp_mmhg` 必须与该收缩压来自同一次测量，不得拼接不同时点记录；
- `spo2_percent` 同时被 PESI 和 C-R 使用，只输出一个事实；
- 亚段与非亚段血栓同时存在时，`highest_thrombus_location=non_subsegmental`；
- `rv_abnormal` 与 `cardiac_biomarker_abnormal` 必须分别提取，不得由其中一项推导另一项。

### 5.2 低血压与 D1

- `vasopressor_used` 和 `fluid_treatment_given` 按字段提示词判断本次急性肺栓塞病程中实际实施的治疗；计划治疗不算已实施；
- 低血压判断复用同一个 `systolic_bp_mmhg`，不再提取单独的事件收缩压；
- `sbp_below_90_duration_minutes` 表示低于阈值的持续时间，不是总观察时间；
- `systolic_bp_drop_mmhg` 表示相对原血压的下降幅度；病历未提供足够信息计算时保持缺失；
- `sbp_drop_gt_40_duration_minutes` 只记录下降超过 40 mmHg 的持续时间；
- 只有病历明确记载低血压已恢复，`hypotension_recovered` 才能为 `true`；仅“给予补液”不足以支持。
- `hypotension_recurred_after_recovery` 记录恢复后是否再次发生低血压，按字段注册表中的三种提取条件判断；它与 E1/D2 所用的“反复或持续低血压”不是同一事实，不能互相填充。即使短暂低血压已足以构成 D1 候选，恢复后复发也须单独提取。

### 5.3 低灌注

- 乳酸输出标准单位下的原始数值；MAP 由程序根据同次收缩压和舒张压计算，LLM 不单独输出 MAP；
- `acute_kidney_dysfunction` 与 `altered_mental_status` 是病历事实判断；
- `cold_clammy_extremities` 按提示词涵盖四肢湿冷、肢端湿冷、末梢湿冷、皮肤湿冷等记载；字段名不限制提示词列出的阳性表述；它与其他低灌注指标为 OR 关系；
- 尿量、心脏指数和 SCAI 不属于当前输入 Schema，不得加入事实表。

### 5.4 E

- 仅明确为难治性心源性休克时，`refractory_cardiogenic_shock` 才能为 `true`；
- `no_rosc_after_30_minutes` 是完整条件“心脏骤停经 30 分钟复苏后仍未恢复自主循环”，不再单独提取“发生心脏骤停”；
- 仅记录心脏骤停、未记录 30 分钟复苏结局时，该字段必须保持缺失。

### 5.5 呼吸分型 R

- `oxygen_required` 虽沿用原字段名，当前提示词判断的是病历是否记载实际吸氧；
- `nasal_cannula_over_6_l_min` 表示是否存在鼻导管吸氧流量严格大于 6 L/min；明确为 6 L/min 时填 `false`；已记载鼻导管吸氧但未记载流量时，提示词按 2 L/min 判断为 `false`；完全未记载鼻导管吸氧时仍为缺失事实；
- 面罩吸氧写入 `face_mask_oxygen`，不得根据未记录的流量进行补推；
- 无创和有创机械通气必须分别写入对应字段；
- 一项治疗事实不得自动推导其他未明确记录的呼吸字段。

## 6. 完整性要求

提取输出必须恰好包含当前 Schema 的 35 个原始字段。`systolic_bp_mmhg` 同时用于低血压、PESI 和 MAP；`spo2_percent`、`respiratory_rate_bpm` 同时用于 PESI 和 C-R，`altered_mental_status` 同时用于 PESI 和低灌注；每项在 JSON 中只出现一次。

字段名清单由代码中的 `FIELD_SPECS` 生成或核对；本规范不维护第二份完整字段名列表。

## 7. 修正契约

审核不通过后，提取 Agent 接收原始病历、上一版事实表和审核意见。修正过程必须：

1. 逐项核对审核问题；
2. 回到原始病历验证，而不是直接采纳审核建议中的候选值；
3. 修正受影响字段；
4. 检查修改是否影响其他字段；
5. 返回一份新的完整事实表。

上一版事实表只能作为定位和比较依据，不能替代病历证据。

## 8. 审核契约


审核 Agent 必须检查：

- 是否遗漏病历明确记录的固定字段；
- `value` 是否与证据和原始病历一致；
- 否定、既往史、当前状态和时间点是否识别正确；
- 数值及单位转换是否正确；
- 缺失事实和明确阴性是否区分正确；
- 是否包含全部固定字段且没有未知字段；
- 证据是否真实、充分且可追溯。

审核输出结构：

```json
{
  "approved": false,
  "issues": [
    {
      "field": "age_years",
      "issue_type": "incorrect_value",
      "reason": "病历记录63岁，当前值为36",
      "suggestion": "重新核对年龄原文"
    }
  ]
}
```

约束：

- 输出必须且只能包含 `approved`、`issues`；
- `approved=true` 时，`issues` 必须为空数组；
- `approved=false` 时，`issues` 必须至少包含一项；
- 单项问题必须包含 `field`、`issue_type`、`reason`、`suggestion`；
- 整体结构问题的 `field` 可以写为 `__structure__`；
- 审核 Agent 只指出问题，不直接输出修改后的事实表。

## 9. 示例

### 9.1 已知数值

病历：`患者年龄为81岁。`

```json
{
  "age_years": {
    "value": 81,
    "mentioned": true,
    "evidence": "患者年龄为81岁"
  }
}
```

### 9.2 明确阴性

病历：`否认恶性肿瘤病史。`

```json
{
  "cancer_history": {
    "value": false,
    "mentioned": true,
    "evidence": "否认恶性肿瘤病史"
  }
}
```

### 9.3 缺失事实

病历未记录舒张压：

```json
{
  "diastolic_bp_mmhg": {
    "value": null,
    "mentioned": false,
    "evidence": null
  }
}
```

### 9.4 不充分证据

病历：`给予补液治疗。`

以下输出无效，因为原文没有说明补液后血压恢复：

```json
{
  "hypotension_recovered": {
    "value": true,
    "mentioned": true,
    "evidence": "给予补液治疗"
  }
}
```

正确做法是将该字段保持为缺失，除非病历其他位置提供恢复证据。

## 10. 验收清单

提交给规则引擎前，必须确认：

- [ ] 顶层是 JSON 对象；
- [ ] 恰好包含当前 `FIELD_SPECS` 定义的 35 个字段；
- [ ] 每个字段只包含 `value`、`mentioned`、`evidence`；
- [ ] 已知事实具有合法类型和非空原文证据，或是已配置字段的 `false/true/null` 例外；
- [ ] 缺失事实严格使用 `null/false/null` 组合；
- [ ] 明确阴性使用 `value=false, mentioned=true`；
- [ ] 数值已转换为标准单位；
- [ ] 没有根据阈值、常识或其他字段补猜缺失值；
- [ ] 没有输出等级、规则结论或未知字段；
- [ ] 修正请求返回的是完整事实表。

## 11. 当前限制

- 每个字段只支持一个最终值和一个证据字符串；
- Schema 不表示置信度、时间戳、信息来源层级或冲突状态；
- 对临床概念型布尔字段的判断仍依赖模型理解；
- 提取与审核使用相同字段说明，且当前默认使用同一模型服务；
- 运行时解析器校验结构和类型，但不校验数值生理范围或证据是否确实来自原文。
